# Правила обработки заказов Organicare (Гонконг) — накопленный опыт

## 1. Разбор текста заказа
- Каждая строка "N стол [премиум] [исключения] M комплект(ов)" → отдельная запись
- Премиум-исключения / премиум-основной / стандарт-основной / доп / бракераж / стандарт-исключения — извлекаются раздельно
- Не объединять записи по совпадению текста исключения — только по факту одной строки заказа

## 2. Шапка (строки 1–4)
- **Упаковка (строка 1)** определяется ПОЗИЦИЕЙ колонки, не текстом исключения:
  - D (Оставлять на производстве) — отдельная, всегда БЕЛАЯ
  - E..(премиум-основной включительно) — ПЛАСТИК/ПРЕМИУМ, серая заливка (CCCCCC)
  - стандарт-основной и далее — КРАФТ/СТАНДАРТ, белая заливка
- **D4 "Оставлять на производстве"** — константа 2, НО применяется формулой только к салату/супу/основному горячему+гарниру на ОБЕД и УЖИН. НЕ на завтрак, НЕ на расходники (чай/сахар/лимон/масло/хлеб/напиток)
- **E (БРАКЕРАЖ)** — та же логика, что и D (только основные блюда обед/ужин), число нужно уточнять/оценивать, из текста заказа впрямую не берётся
- **Боулы** (БОУЛ ОВОЩНОЙ и т.п.) — только ПРЕМИУМ колонки, никогда не стандарт

## 3. Форматирование (снято с реальных файлов 23/24.08.2026)
- **B2 "ИСКЛЮЧЕНИЯ"** — уникальная ячейка Arial 24, белая заливка
- **Строки 1–2** (упаковка + названия исключений) — Nunito 12, серая(премиум)/белая(стандарт) заливка
- **Строка 3** (номера столов) — Nunito 16, ГОЛУБАЯ заливка (D0E0E3) везде, без разделения премиум/стандарт
- **Строка 4** (количества) — Nunito 16, белая заливка
- **Строки блюд (5+)**: колонка B — Nunito 14, слева; остальные — Nunito 16, по центру
- **Заливка строки блюда** — ОДНА на всю строку (серая = входит в основное меню, белая = замена под конкретное исключение). Если ячейка очищена из-за конфликта состава — заливка остаётся как у всей строки, НЕ сбрасывается в "нет цвета"
- **Никаких розовых/красных пометок конфликта** — конфликтная ячейка в серой строке просто остаётся пустой, без цвета и без комментария (как в реальных файлах)
- **Ширина колонок**: A=4.75, B=54.88, C=22.88, D=15.88, E=17.63, F=14.63 — остальные (G и далее) БЕЗ явной ширины (дефолт Excel)
- Границы у колонок, добавленных сверх исходного шаблона, нужно вручную скопировать с соседней "родной" колонки — иначе они визуально выпадают из таблицы

## 4. Логика замены блюд
- Если стандартное блюдо дня подходит клиенту → 1 в СЕРУЮ (базовую) строку по формуле "=X4"
- Если не подходит → искать среди уже существующих альтернативных (белых) строк в этом же приёме пищи; если такой нет — создать новую
- Проверка "подходит/не подходит" — строго по СОСТАВУ блюда, включая синонимы:
  - лактоза → молоко/сливки/творог/сыр/кефир/йогурт/сметана/мусс
  - рыба → треска/форель/кефаль/судак/лосось/сельдь
  - мясо → курица/говядина/свинина/баранина/индейка/ветчина
  - злаки → крупа/мука/хлеб/булочка/кекс/печенье
  - цитрус → лимон/апельсин/мандарин
  - веган (без доп. уточнений "рыбу/молочку можно") → исключает мясо И яйца по умолчанию
- "Сырые" ингредиенты без "Состава" в меню (сахар, лимон, чай, хлеб, напиток, масло, кефир, йогурт, ветчина, яйцо) — их состав нужно прописывать вручную, проверка по ним иначе не сработает
- Ветчина в этом меню — ИЗ ИНДЕЙКИ, не свинина
- НИКОГДА не изобретать замену без прецедента — если в реальных обработанных вкладках есть похожий случай, использовать именно его (например, "Рыбная котлета" для "без мяса, но с рыбой")
- Если подходящей замены категорически нет нигде — создать её на основе имеющихся в меню продуктов (например, йогурт вместо салата для "без овощей", рыба вместо мяса и т.п.), а не оставлять пациента совсем без блюда
- Один и тот же клиент не должен получать одинаковое блюдо дважды за приём пищи; на обед и ужин — разные позиции

## 5. Частые баги, которые нужно ловить самопроверкой
- Опечатки в названиях блюд ломают сопоставление состава (например "пшенная"/"пшеная", "капченым"/"копченым") — сопоставление должно быть терпимо к отличию в 1 букву
- Короткие названия ("Овощной") могут ложно сматчиться не с тем блюдом — если название неполное, лучше исправить на каноническое
- "Мускатный орех" — это специя, не аллерген-орех, не должен триггерить "без орехов"
- "Яйцо куриное" — это яйцо, не мясо курицы, не должно триггерить "без мяса"/"без курицы"
- При объединении негативных формулировок в собственном описании состава ("без сахара", "без молока") — эти слова сами ложно совпадают при последующей проверке; формулировать состав без отрицаний
- После вставки/удаления строк ВСЕГДА переустанавливать формулы "Итого" (=SUM(Dr:Ur)) по актуальным номерам строк — они не сдвигаются автоматически
- После любых правок — проверять на нулевые (по итогу) и полностью пустые строки, удалять их

## 6. Источники данных
- `all_recipes.json` / `all_recipes.pkl` — словарь состава блюд (очищать от опечаток, ~80 позиций)
- `full_menu.json` / `full_menu.pkl` — состав по дням недели из официального меню Гонконг
- Реальные обработанные вкладки — источник прецедентов для замен, НЕ копировать целиком вместо своей обработки, но сверяться после того, как обработал сам
